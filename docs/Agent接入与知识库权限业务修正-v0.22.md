## 业务对象

日常对象是知识库、目录、资料、治理任务和正式知识。当前业务没有独立的“项目”对象，不要求用户为了管理资料先创建项目、理解项目角色或项目组织。

团队/组织用于隔离不同团队的账号和资料；有多个团队时才需要切换与团队管理。它不是每次治理资料时必须配置的业务步骤。

现有 Project 承载资料、任务、规则、发布及权限的技术隔离边界。后续须核对其与用户所见知识库的实际映射，再提供兼容适配；不直接合并数据库、不把多个边界自动授权互通、不删除 ops 与历史审计。不能只把所有“项目”字样替换成“知识库”，就认定模型已修正。

## 外部 Agent 接入

接入方向是：外部 Agent 作为调用方，凭本平台发给它的访问凭证，读取获授权知识库中的已发布知识。它无需安装平台的治理 Agent。

主页面呈现调用方清单：名称、负责人、允许读取的知识库/目录、到期时间、启停状态和最近调用结果。新增调用方用抽屉填写名称、用途、范围和有效期；保存后提供凭证、标准接口及调用示例。详情提供试读、凭证更新、暂停/撤销及调用记录。凭证不展示在列表、URL、日志或浏览器长期存储中。

默认权限只读正式知识，不包含原件、治理中间结果、候选、规则修改、审核或发布。授权扩展必须独立声明，不能因“接入 Agent”自动获得整理和写入权限。后续新增正式内容是否可读取取决于明确授权的范围；撤回、来源限制、撤权、到期须在每次请求时生效。

旧页面控件处理：

| 当前内容 | 原实际用途 | 调整方向 |
| --- | --- | --- |
| 安装治理 Agent | 创建内部运行身份及安装级能力上限 | 从外部调用方流程移出；内部兼容管理保留历史 |
| 项目绑定 | 为安装身份指定可用资源 | 外部调用方直接选择知识库与目录范围 |
| 人员委派 | 人员把有限权限交给一次执行链 | 不作为外部只读调用方的用户操作步骤 |
| 签发短期运行 | 为旧运行链签发临时令牌 | 调用方凭证生命周期由平台管理，不让用户逐次创建运行 |
| 安装额度/份额/运行额度 | 旧运行链的抽象授权额度 | 从外部只读接入表单移出，不当作金额预算 |
| 来源检查、规则生成 | 平台内部治理/规则能力 | 回归治理任务或规则功能，不混入外部读取入口 |

代码核查：`general_agent_knowledge.py` 当前明确依赖 AgentRun、安装/绑定/委派及其实时核验；标准接口 `/api/v1/agent-runs/{run_id}/general-knowledge/query` 仍以运行身份读取。已有版本、引用、撤回/撤权校验可以复用，但独立外部调用方身份、凭证与目录授权管理尚须实现。已有独立 HTTP 消费者验证不等于本节管理流程已经完成。禁止把旧链藏到一个“新增调用方”按钮后就宣称完成业务分离。

## 人员与知识库权限

入口统一按“成员与权限”理解。成员管理解决谁可登录、谁已加入团队；知识库权限解决谁可对哪些资料做什么。团队切换/知识库管理放在相应范围入口，移除日常权限页中的“项目角色”“组织与项目”导航。

知识库权限默认展示人员与实际授权摘要：姓名/邮箱、知识库范围、目录范围、可执行动作、有效期、是否有效。按人员查看可操作的资料，按目录查看哪些人能操作；添加/调整授权使用抽屉，不让用户先组合数张角色表。

动作含义：

| 动作 | 业务含义 |
| --- | --- |
| 管理 | 管理知识库设置、人员及范围授权 |
| 整理 | 导入、补充资料并执行治理任务 |
| 审核 | 核对治理成果及证据，作出审核决定 |
| 发布 | 将已满足审核条件的成果提供正式使用，并按授权撤回 |
| 读取 | 查阅获授权的正式知识；原件查看另按实际授权说明 |

角色只能作为配置快捷方式，必须展示包含的动作。实际权限仍受有效成员资格、知识库/目录范围、来源限制及指定任务职责共同约束；不能根据角色名称就宣称人员可以审核或发布。现有 publisher 基础角色不等于每个任务的发布授权。界面需明确展示“该任务另有指定责任人”等限制，并支持定位授权来源。

人员和 Agent 可以共享范围表达与有效性原则，各自使用独立身份与凭证。禁止把人的登录账号或本人临时运行令牌作为外部 Agent 的长期身份。

## 实现与验收顺序

1. 固定知识库与现有技术隔离边界的兼容映射，保留原数据/权限/审计。
2. 实现独立调用方登记、凭证生命周期、正式知识目录范围授权及逐请求核验，再建设对应列表/抽屉。内部治理运行链保留受控兼容入口。
3. 人员页围绕人员、资料范围和实际动作展示与编辑；任务独立职责继续在任务中明确，不扩大旧权限。
4. 用两个独立调用方与多人员验证允许范围、跨范围拒绝、到期、停用、凭证更新、撤权、来源受限与撤回；核对正式版本/引用和审计。验证期间使用隔离数据，不自动接入真实 Agent。

本段为首次业务纠偏时的实施计划；随后实际落地、验证和本机更新以上方“已实施范围”及implementation-status.md最新批次为准。
