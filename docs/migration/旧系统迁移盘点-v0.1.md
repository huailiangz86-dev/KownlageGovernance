## S0 盘点与 dry-run 契约

1. 每类旧表/对象输出总数、租户/部门分布、空归属、重复旧 ID、缺对象、SHA-256 不符和无法读取数；抽取连接只读。
2. 建 legacy_id_map(source_system, entity_type, legacy_id, target_organization_id, target_project_id, target_id, source_hash, migration_batch, status, reason)。同一旧键重跑得到同一目标 ID；冲突可导出核对。
3. dry-run 先检查归属、权限、格式、对象存在性和证据可定位性；输出可迁移、需人工映射、隔离、失败四类及原因，不创建发布事实。
4. 非生产环境试导入一个项目，核对记录数、哈希、目录关系、版本、草案状态与拒绝路径；保留可重跑、可回滚批次标识。
5. 逐项目切流时比较旧新结果与权限。新入口不得借旧接口扩大授权；旧消费者停用前准备回到旧只读入口的预案。

## 仍需迁移输入

- AIOps 生产数据的只读元数据导出，以及要迁入的运营配置和历史记录范围；代码源已定位。
- 旧数据库和对象存储的只读导出方式，首批试点项目对应的旧租户/部门/目录范围；导出数据和凭据不提交仓库。
- 首批与封存的第二批脱敏资料、首个真实 Agent 和发布目的地。

这些数据缺失时可继续 S1 目标模型与本地样本，但不能声称旧数据或运营配置已迁移。

## 本地预检工具

脚本：[preflight_knowledgehub.py](../../scripts/migration/preflight_knowledgehub.py)。输入为只读导出的 JSON 元数据，不连接数据库、不读取对象正文、不写入旧系统。导出格式：顶层可含 knowledge_directories、knowledge_files、knowledge_cards 三个数组，每条记录至少含 id、tenant_id、organization_id；文件还需 sha256 和 oss_key 或 evidence_path。映射文件格式如下：

    {
      "mappings": [{
        "tenant_id": "旧租户 ID",
        "organization_id": 7,
        "target_organization_id": "目标组织 ID",
        "target_project_id": "目标项目 ID"
      }]
    }

运行示例：

    python scripts/migration/preflight_knowledgehub.py --export old-metadata.json --mapping approved-mapping.json --output preflight-report.json

报告仅含旧 ID、目标 ID、状态和原因码，不复制正文。ready 仅表示元数据具备后续试导入条件；对象存在性、实际字节哈希、旧权限和卡片证据尚未验证，不能据此发布知识。原始导出和报告可能包含客户标识，应放在受控目录，避免提交仓库。
