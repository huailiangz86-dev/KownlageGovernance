Sprint 按依赖排序，不预填周数或人力估计。S0 至 S2 可提前制作前端壳和测试夹具，但演示数据必须标明模拟；出口以前后端联动与回归为准。

## 贯穿场景

使用原型中的“新客户用已批准报价、老客户按有效合同、渠道客户待确认”纵向样本：上传报价 PDF、合同 DOCX、会议纪要 MD 和不可解析 PDF；查看覆盖与证据；人员确认限定规则；试运行；派生修订；验证；人员发布；外部 Agent 查询。每一步留存来源版本、规则版本、确认人、快照和未完成项。第二批加入客户例外与来源变化，封存至 S6。

## 通用完成条件

1. 相关变更包含数据库迁移、API 契约、服务端鉴权、审计与前端状态；静态页面不能代替后端完成。
2. 写入具幂等键，更新具 If-Match；异步工作单元重验授权、输入版本和预算。
3. 自动回归覆盖正常、跨项目、失权、输入变化、解析失败、预算不足和重复请求中的适用路径。
4. 日志、错误、ops 摘要、通知不包含原文、密钥或完整业务意见。
5. PRD、架构、原型有差异时先记录决策，再更新契约。

## Sprint 前置决策

| 决策 | 最迟节点 | 当前可继续的工作 |
|---|---|---|
| 试点是否要求数据库级租户隔离；MySQL 8 或 PostgreSQL/独立库 | S1 生产 schema 前 | 领域/API 契约和本地样本 |
| 旧租户、部门、公共/NULL 数据到新组织/项目的映射 | S0 试迁移前 | 未归属记录隔离待审 |
| AIOps 运营配置和历史数据的迁移范围 | S0 试迁移前 | 源代码已盘点；平台控制面与每组织 ops 分开建模 |
| 预算、保留期、失权删除时限、模型处理地区 | S2 试点上传前 | 配置字段和拒绝默认值 |
| 首个真实 Agent、发布目的地及撤回回执能力 | S4 目的地实现前 | 本地快照与 mock 契约 |
| 业务确认人配置、支持访问时长、break-glass | S1/S3 对应流程启用前 | 高影响动作保持关闭 |

首版暂以架构稿的模块化单体、独立 Worker、MySQL 8 为设计基线；如需数据库级租户隔离，生产 schema 前重定数据库。旧数据先盘点、映射、dry-run、试导入、核对，再逐项目切流。旧标签、卡片和有效期不得自动成为已确认、已发布知识。

当前继续补齐 S0 真实元数据导出与审批映射；S1 已完成首批组织/ops 事务边界和人员权限领域层，后续接入 HTTP API、成员管理、Agent 绑定与撤销及前端联调。
