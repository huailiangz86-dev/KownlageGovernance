# 资料治理 Agent PRD

版本：v0.1 评审稿（已由 [v0.2 研发规格稿](./资料治理Agent_PRD-v0.2.md) 细化更新）  
日期：2026 年 9 月 27 日  
状态：用于补齐首版产品范围、页面与验收；不是研发排期或对外功能承诺。

## 1. 产品目标与边界

资料治理 Agent 面向个人与小团队，把持续变化的工作资料维护为可追溯、按条件适用、可供人和外部 Agent 使用的有效知识。AI 负责盘点、关系候选、问题诊断、修订提案与已授权的可恢复处理；人只对业务事实、规则范围、高影响动作和发布作决定。

首版以一个项目／主题为边界，支持上传的 Markdown、文本、DOCX、可提取正文的 PDF。默认只读诊断，修复结果为派生版本，不覆盖或删除原件。

首版不做通用问答产品、全企业知识迁移、全量连接器、原件自动写回、任意外部 Agent 的执行权限或无证据的事实补全。

## 2. 成功标准

一个试点任务完成时，用户能清楚回答：哪些资料被检查、AI 做了什么、哪些问题仍需决定、哪条规则在何处适用、哪一版知识已经发布、以及下游是否验证收到。

试点指标记录人工总时间、独立核验的误修复与遗漏、第二批未见资料中的规则复用与例外识别、完整成本和真实付费意愿。文件数、模型调用数和健康分不作为成功指标。

## 3. 角色与授权

| 角色 | 可做 | 不能默认做 |
|---|---|---|
| 项目所有者 | 配置项目、成员、来源、预算与发布目的地 | 以所有者身份取代业务事实确认 |
| 委托人 | 发起任务、限定范围、提交业务意见 | 扩大来源读取或跨项目推广规则 |
| 业务确认人 | 确认事实、条件、例外和规则范围 | 发布未经验证的修订 |
| 发布人 | 发布已验证的知识快照、确认恢复 | 跳过待决策事项或来源权限 |
| 外部 Agent | 在授权范围读取知识、提交线索或任务 | 凭文字意见确认、修订、发布或覆盖原件 |

个人模式可由同一人承担多个角色，但每个关键动作仍记录实际确认人和时间。

## 4. 核心对象与状态

| 对象 | 必要字段 | 核心状态 |
|---|---|---|
| 项目 | 名称、用途、负责人、默认预算、成员 | 正常、暂停、归档 |
| 来源／来源版本 | 位置、权限、哈希、读取状态、保留策略 | 可读、读取失败、权限撤回、已删除、已变化 |
| 问题组 | 类型、证据、影响对象、不确定性、阻塞范围 | 分析中、待决定、已解决、已忽略 |
| 决策 | 原始意见、结构化解释、确认人、范围 | 草案、已确认、已撤销 |
| 规则版本 | 条件、动作、例外、验证样本、作用范围 | 草案、试运行、已生效、暂停、替代、撤销 |
| 修订集 | 输入版本、规则版本、前后差异、验证结果 | 草案、修复中、验证失败、待发布、已恢复 |
| 知识版本 | 内容、出处、条件、生效时间、责任人 | 待确认、未发布、当前生效、未来生效、替代、撤销、受限 |
| 发布快照 | 知识版本集合、目的地、回执 | 待确认、本地生效、已接收、已验证、同步失败 |

“规则已确认”“修订已验证”“知识已发布”“下游已验证”必须在界面和数据上分离。最新修改时间、单个来源的验证徽章和用户沉默均不能作为业务权威的替代。

## 5. 主路径

### 5.1 首次治理

创建项目 → 上传资料 → 选择目标与预算 → 只读诊断 → AI 聚合问题组 → 用户对话澄清 → 规则草案与试运行 → 生成派生修订 → 验证 → 单独发布 → 记录下游状态。

验收：用户不必逐份打开文件；每个发布结论能回到来源、规则和验证样本。

### 5.2 增量维护

来源变化或规则／权限变化 → 判定受影响对象 → 确定性检查与候选召回 → 已授权规则试运行／生成提案 → 例外进入决策队列 → 验证 → 单独发布或保留草稿。

验收：第二批资料不会因曾经批准规则而自动成为已发布事实；无变化内容不重做全库处理。

### 5.3 外部 Agent 使用

外部 Agent 带调用方身份、项目与适用上下文请求知识 → 服务校验读取权限、发布状态与条件 → 返回内容、出处、版本、条件、未解决事项；写入操作分别经过任务、确认与发布授权。

验收：缺少条件时返回澄清要求，不任选一个“最新”答案；离线导出不宣称能实时撤回。

## 6. 信息架构与页面规格

### 6.1 工作台

目的：让用户一眼知道 AI 正在做什么，以及自己只需决定什么。

模块：新建委托、按影响排序的决策队列、进行中任务、最近修订与发布、来源异常、当前维护范围。决策卡必须显示影响对象数、建议、关键证据、可选动作和阻塞范围。

状态：首次空态引导创建项目与上传；无待决策态说明检查范围与最近完成时间；预算临界、来源权限撤回、验证失败使用需行动告警；任务失败保留检查点与恢复入口。

### 6.2 整理任务

目的：在一条任务中完成目标、对话澄清、证据查看、规则提案、修订和验证。

布局：任务抬头（范围、授权、预算、阶段），中栏对话与问题组，右栏证据／影响／差异，底部上下文动作。每次 AI 提议都明确“本次修订”“项目规则”“仅供参考”之一。

状态：分析中显示可继续项与已检查范围；待决定只阻塞关联工作；暂停／取消列出已完成结果；来源在处理期间变化时显示重新核对，而非覆盖新版本。

### 6.3 决策队列

目的：跨任务聚合同类业务不确定性，而非生成逐文件审批清单。

列表字段：问题类型、影响资料／知识数、风险、推荐、负责人、截至时间、状态。详情包含对立证据、影响预览、对话输入、可选范围（本次／项目规则／暂缓）和需要的确认角色。

批量动作只允许无业务歧义的同类低风险事项；“全部接受”不能用于事实冲突、规则扩域或发布。

### 6.4 资料来源

目的：管理接入边界、读取与证据，而非人工分类。

列表与详情显示来源、版本关系、权限、解析状态、最近检查、关联问题／知识／任务。支持上传、缩小范围、暂停监测、查看原文与处理依赖。权限撤回后限制读取并展示受影响输出；暂停监测不等同删除或立即失效。

### 6.5 有效知识

目的：交付可引用的有效知识视图，而非另一份摘要。

列表字段：结论、条件、时间、状态、来源、发布快照、责任人。详情以“结论—条件—证据—替代关系—使用限制”组织；试读器输入项目、客户类型和业务日期，返回适用内容或澄清请求。

### 6.6 处理规则

目的：让用户检查 AI 学到的可复用处理方式。

规则卡显示自然语言规则、范围、条件、例外、允许动作、证据、确认记录、版本和试运行样本。编辑经由对话或结构化修改生成新版本与影响预览；暂停／撤销会标识受影响修订与知识，不能静默改写历史。

### 6.7 修订、发布与版本

目的：将“生成结果”变成可控交付。

修订详情显示输入、规则、差异、验证案例与失败项。发布向导分为内容选择、未解决事项、目的地／回执策略、确认。发布后分别展示本地生效、下游接收、下游验证、失败重试；恢复为新发布而非删除历史。

### 6.8 Agent 接入

目的：配置调用主体和审查活动，而不是只发一个密钥。

接入卡包含调用方、客户／项目范围、读取知识范围、允许动作、最近调用、当前发布版本。展示任务、问题、意见、提案、有效知识、发布结果的接口示例与权限结果；调用方意见标记为未验证线索。

### 6.9 预算、权限与设置

目的：在工作开始前明确自动化边界和成本行为。

显示成员角色、来源权限、数据保留、默认自动动作、预算分项与告警阈值。预算不足时提供缩小范围、继续、延期；不把未处理内容标为已检查。持续维护的触发来源、规则、解析方法和权限变化均可见。

## 7. P0 交互与验收

| 编号 | 用户故事 | 验收 |
|---|---|---|
| P0-1 | 我能发起一个有范围和预算的治理任务 | 默认只读；范围、原件处理方式、预算都可见 |
| P0-2 | 我只收到少量高影响决策组 | 每项显示证据、影响与推荐；不能把沉默当批准 |
| P0-3 | 我能把意见转成受限规则 | 规则具备范围、条件、例外、版本与试运行，不自动跨项目 |
| P0-4 | 我能看到修复了什么且原件不受影响 | 修订为派生版本，能回到输入版本与规则 |
| P0-5 | 我能单独发布并检查下游状态 | 修订完成不等于发布；发布不等于下游验证 |
| P0-6 | 外部 Agent 只能在权限内读取有效知识 | 响应含来源、条件、版本与未解决事项；写入操作分权 |
| P0-7 | 第二批资料可复用规则但不会自动发布 | 明确显示增量范围、例外与新发布确认 |

## 8. 异常与边界

无法解析、来源权限撤回、规则冲突、意见不清楚、模型中断、验证失败、预算不足、下游同步失败均须保留已完成部分与下一步，不能显示“任务完成”。原始资料在处理期间变化时必须重新核对版本。任何来自资料正文的命令都只视为待分析内容，不取得执行权限。

## 9. 原型范围

原型应覆盖上述九类页面中的 P0 关键页及其空态、进行中、待决策、验证失败、待发布、已发布／同步失败状态。原型用模拟数据演示首次治理与第二批增量治理；不伪装为真实扫描、Agent 调用、权限校验或成本测量。

进入研发前，还需补齐字段字典、状态迁移图、接口契约、测试资料集、指标埋点与真实客户试点评估。
